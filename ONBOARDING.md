## Шаг 0. Договорённости

Прежде чем что-то ставить — три вещи, которые определят, получится у тебя или нет.

**1. Ошибки — это рабочий процесс, а не признак, что ты тупишь.**
Сегодня что-то сломается. В следующий раз тоже. И потом, когда будешь опытной, — тоже, просто ошибки станут интереснее. Инженер отличается от новичка не тем, что у него не ломается, а тем, что он умеет читать сообщение об ошибке. Красный текст в терминале — это не крик, это описание проблемы. Читай его целиком, особенно **последнюю строку**.

**2. Гуглить — можно и нужно. Копировать не глядя — нет.**
Правило из твоего плана: **сначала борись сама, только потом иди за подсказкой**. Решение, найденное после борьбы, запоминается. Прочитанное сразу — испаряется.

**3. Сегодня цель — не понять, а запустить.**
Понимание придёт с практикой. Сегодня задача механическая: собрать станок, на котором будешь работать дальше.

## Шаг 1. Терминал

**Зачем.** Терминал — это способ разговаривать с компьютером текстом вместо мышки. Кажется архаикой, пока не поймёшь, что мышкой нельзя описать действие, а текстом можно: записать, повторить, отправить другому человеку, автоматизировать. Весь ML-мир живёт в терминале. Начинаем с него.

**Делай.**

1. Открой меню «Пуск», набери `Terminal`. Если Windows Terminal есть — открывай его.
2. Если его нет — поставь из Microsoft Store (ищи «Windows Terminal»), он бесплатный. Не заменяй его на старую чёрную `cmd`, она хуже во всём.
3. Открылось окно с текстом вида `PS C:\Users\ТвоёИмя>`. Это PowerShell — им и будем пользоваться.

Попробуй три команды. Набирай руками, не копируй — пальцы должны запомнить:

```powershell
pwd
```
Показывает, в какой папке ты сейчас находишься. «Где я».

```powershell
ls
```
Показывает содержимое текущей папки. «Что вокруг».

```powershell
cd Desktop
```
Переходит в папку `Desktop`. «Иди туда».

Теперь вернись обратно:

```powershell
cd ..
```

`..` означает «на уровень вверх». Эти четыре команды — 90% работы с терминалом. Остальное добавится само.

**Проверь.** Ты можешь, не подглядывая, ответить: как узнать где я, как посмотреть что в папке, как зайти в папку и как выйти из неё.

**Если сломалось.**
- `ls` не работает → у тебя открыт `cmd`, а не PowerShell. Закрой и открой Windows Terminal.
- Пишет «имя не распознано как имя командлета» → опечатка. Проверь букву за буквой.

## Шаг 2. Git

**Зачем.** Git — машина времени для кода. Он запоминает каждое состояние твоих файлов, и ты в любой момент можешь вернуться назад, сравнить «было/стало», или посмотреть, что именно сломало работавший вчера код.

Из твоего плана, раздел «Пять способов провалить»: *«Работать без логов и git»* — потом не воспроизведёшь собственный результат и потеряешь кучу сил. Поэтому git ставится в первый день, а не «когда понадобится».

**Делай.**

Установи через `winget` — это встроенный в Windows установщик программ:

```powershell
winget install --id Git.Git -e
```

Согласись со всем, что спросит. После установки **закрой терминал и открой заново** — иначе он не увидит новую программу.

Теперь представься гиту. Он подписывает твоим именем каждое сохранение:

```powershell
git config --global user.name "Твоё Имя"
```

```powershell
git config --global user.email "твоя@почта.com"
```

Почту укажи ту же, на которую будешь регистрировать GitHub в Шаге 6.

И ещё одна настройка — имя главной ветки. Так принято сейчас везде:

```powershell
git config --global init.defaultBranch main
```

**Проверь.**

```powershell
git --version
```

Должна появиться строка вида `git version 2.47.0`. Номер может отличаться — важно, что версия вообще выводится.

```powershell
git config --global user.name
```

Должно вывести твоё имя.

**Если сломалось.**
- `winget` не найден → у тебя старая Windows 10. Скачай установщик вручную с git-scm.com, ставь со всеми галочками по умолчанию.
- `git --version` не работает после установки → ты не перезапустила терминал. Закрой окно полностью и открой заново.

## Шаг 3. uv — управление Python

**Зачем.** Тут нужно объяснить чуть подробнее, потому что это место, где новички застревают надолго.

У каждого проекта свой набор библиотек и своя версия Python. Если ставить всё «в систему» общей кучей, то рано или поздно один проект потребует одну версию библиотеки, другой — другую, всё сломается разом, и починить будет почти невозможно. Это классическая боль, у неё даже есть имя — «dependency hell».

Решение: **виртуальное окружение** — отдельная изолированная коробка с Python и библиотеками под каждый проект. Сломала коробку — выбросила, собрала новую, остальное не пострадало.

`uv` — современный инструмент, который делает эти коробки. Он же ставит сам Python, так что отдельно Python скачивать не нужно. Он быстрый и не капризный — в отличие от conda, которую ты встретишь в старых туториалах.

**Делай.**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Эта команда скачивает установочный скрипт и сразу выполняет его. После установки **снова закрой и открой терминал**.

**Проверь.**

```powershell
uv --version
```

Должно вывести версию, например `uv 0.5.11`.

**Если сломалось.**
- «Выполнение сценариев отключено в этой системе» → Windows блокирует скрипты. Часть `-ExecutionPolicy ByPass` как раз это обходит — проверь, что скопировала команду целиком, вместе с ней.
- `uv` не найден после установки → перезапусти терминал. Если не помогло — перезагрузи компьютер, это реально помогает с переменными среды в Windows.

## Шаг 5. Твой репозиторий

Здесь начинается настоящая работа. Ты создашь рабочую папку своими руками, а не получишь готовую.

**Зачем.** Структура папок — это не украшательство. Довольно скоро у тебя будет несколько сотен файлов, и найти «тот скрипт, где я разбиралась с broadcasting» можно будет только если с первого дня всё лежит по местам.

### 5.1. Открой папку проекта

В VS Code: `File → Open Folder`, выбери папку `skill-boost` (ту самую, где лежит этот файл). Открой встроенный терминал `` Ctrl+` ``.

Убедись, что ты в правильном месте:

```powershell
ls
```

Должны быть видны `ONBOARDING.md`, `README.md`, папки `plans` и `notes`.

### 5.2. Включи машину времени

```powershell
git init
```

Одна команда — и папка стала репозиторием. Внутри появилась скрытая папка `.git`, где git хранит всю историю. Трогать её не нужно никогда.

### 5.3. Скажи гиту, что не сохранять

**Зачем.** В репозиторий попадает только то, что ты написала сама. Виртуальное окружение (сотни мегабайт), датасеты (гигабайты) и веса моделей — не попадают: они восстанавливаются или скачиваются, а хранить их в истории значит быстро убить репозиторий.

Создай файл `.gitignore` в корне папки (`File → New File`, назови ровно `.gitignore`, с точкой в начале) и вставь в него:

```gitignore
# Виртуальное окружение — пересоздаётся одной командой
.venv/
__pycache__/
*.pyc

# Данные и модели — слишком тяжёлые для git
data/
*.csv
*.wav
*.pt
*.ckpt
checkpoints/

# Служебное
.ipynb_checkpoints/
.ruff_cache/
.DS_Store
```

Сохрани — `Ctrl+S`.

### 5.4. Создай окружение

```powershell
uv init --name skill-boost --python 3.12
```

Появился `pyproject.toml` — паспорт проекта: какая версия Python, какие библиотеки. Если создался файл `main.py` или `hello.py` — удали его, он нам не нужен.

Теперь ставим библиотеки для первой фазы:

```powershell
uv add numpy pandas matplotlib jupyter ruff
```

`uv` сам создаст коробку `.venv` и положит туда всё нужное. Обрати внимание, как быстро — это одно из главных его достоинств.

**Что ты только что поставила:**
- `numpy` — массивы и математика. Фундамент всего ML, дальше он будет везде.
- `pandas` — таблицы, чтение CSV.
- `matplotlib` — графики.
- `jupyter` — ноутбуки для экспериментов.
- `ruff` — проверка чистоты кода.

### 5.5. Создай структуру

Создай папки — можно мышкой в VS Code, можно командой:

```powershell

```

Что где живёт:

| Папка | Что внутри |
|---|---|
| `work/` | Одна папка на блок из плана. Черновой код, эксперименты, вопрос блока. Здесь можно грязно. |
| `projects/` | Артефакты — законченные проекты из плана, каждый со своим README. Здесь чисто. |
| `notes/` | Заметки трёх типов. Главная ценность репозитория со временем. |
| `plans/` | Роадмапы и планы. Читаешь, не меняешь. |

**Проверь.** Команда `ls` показывает: `notes`, `plans`, `projects`, `work`, `.gitignore`, `pyproject.toml`, `ONBOARDING.md`, `README.md`.

## Шаг 6. GitHub и первый коммит

**Зачем.** Git хранит историю на твоём компьютере. GitHub хранит её копию в интернете: компьютер сломается — код цел. Плюс это твоё портфолио: в конце пути ссылка на GitHub будет весомее любого сертификата. Из плана: *«Один проект стоит десяти сертификатов курсов»*.

**Делай.**

1. Зарегистрируйся на github.com — на ту же почту, что указала в Шаге 2.
2. Нажми `+` в правом верхнем углу → `New repository`.
3. Имя: `skill-boost`. Описание: `Мой путь в ML`. Выбери **Private** (сделаешь публичным, когда захочешь показывать).
4. **Ничего не отмечай** в галочках «Add README», «Add .gitignore» — у нас уже всё это есть, а конфликт на первом коммите тебе сейчас не нужен.
5. Create repository.

GitHub покажет страницу с командами. Нужны две строки — возьми их со страницы, они содержат твой логин:

```powershell
git remote add origin https://github.com/ТВОЙ_ЛОГИН/skill-boost.git
```

Теперь первый коммит. Три команды, которые ты будешь повторять сотни раз:

```powershell
git add .
```
«Возьми все изменённые файлы и подготовь к сохранению». Точка означает «всё в текущей папке».

```powershell
git commit -m "Настроила окружение: uv, структура репозитория, первый день"
```
«Сохрани это состояние с подписью». Текст после `-m` — сообщение коммита. Пиши по-человечески: что сделала, а не «update».

```powershell
git push -u origin main
```
«Отправь на GitHub». В первый раз откроется окно браузера — авторизуйся, Windows запомнит доступ навсегда.

**Проверь.** Обнови страницу репозитория на GitHub. Там должны появиться твои файлы. Папок `work`, `projects` и подпапок `notes` пока не видно — **это нормально**: git не хранит пустые папки, они появятся вместе с первым файлом внутри.

**Если сломалось.**
- `failed to push some refs` → на GitHub уже что-то есть (значит, отметила галочку в п.4). Проще всего удалить репозиторий на GitHub и создать заново пустым.
- Просит логин и пароль в терминале → пароль от аккаунта не подойдёт, GitHub их отключил. Должно открыться окно браузера. Если не открылось — переустанови git, галочка Git Credential Manager должна быть включена.

## Шаг 7. Первый код

Теперь то, ради чего всё ставилось.

**Делай.** Создай папку `work/00-python`, в ней файл `hello.py`. Напиши руками — не копируй:

```python
import numpy as np
import matplotlib.pyplot as plt

# 100 точек от 0 до 10
x = np.linspace(0, 10, 100)
y = np.sin(x)

plt.plot(x, y)
plt.title("Мой первый график")
plt.xlabel("x")
plt.ylabel("sin(x)")
plt.savefig("work/00-python/first_plot.png")
print("Готово, картинка сохранена")
```

Запусти:

```powershell
uv run python work/00-python/hello.py
```

`uv run` — важная привычка: он сам берёт Python из твоей коробки `.venv`, и тебе не нужно ничего «активировать». Всегда запускай код через `uv run`.

**Проверь.** В терминале появилось «Готово», в папке `work/00-python` лежит `first_plot.png` с синусоидой. Открой её — она откроется прямо в VS Code.

### Теперь сломай это

Из твоего плана, правила практики: *«Ломай и чини. В каждом блоке намеренно ломаешь что-то и диагностируешь. Это главный рабочий навык и главный источник заметок»*.

Начинаем прямо сегодня. Сделай три поломки, по одной за раз, и **каждый раз прочитай сообщение об ошибке целиком**, прежде чем чинить:

1. Убери строку `import numpy as np`. Запусти. → `NameError: name 'np' is not defined`. Запомни: «не определено» почти всегда значит «забыла импорт или опечатка в имени».
2. Верни импорт, но напиши `np.linspase` вместо `linspace`. Запусти. → `AttributeError`. Это «у модуля нет такой функции» — почти всегда опечатка.
3. Верни как было, но замени `np.linspace(0, 10, 100)` на `np.linspace(0, 10)`. Запусти. → Ошибки нет, но график другой. **Самый важный случай дня:** код может работать и при этом делать не то. Поэтому в ML всегда смотрят на результат, а не только на «упало / не упало».

**Это и есть суть работы.** Не «написать правильно с первого раза», а «понять по симптому, что произошло».

## Шаг 8. Первая заметка

**Зачем.** Заметки — то, что отличает твой план от «я посмотрела курс». Со временем у тебя накопятся сотни заметок, написанных своими словами после того, как ты своими руками во что-то упёрлась. Это и есть твоё понимание в материальной форме.

Три типа, все короткие, все атомарные — одна заметка, одна мысль:

| Тип | Заголовок | Куда |
|---|---|---|
| **Концепт** — почему работает | вопрос | `notes/concepts/` |
| **Рецепт** — как сделать по шагам | глагол | `notes/recipes/` |
| **Грабли** — что сломалось | симптом | `notes/pitfalls/` |

Шаблоны лежат в `notes/_templates/`.

**Делай.** Напиши первую заметку — из третьей поломки, той самой, где ошибки не было, а результат изменился. Скопируй `notes/_templates/pitfall.md` в `notes/pitfalls/grafik-drugoy-bez-oshibki.md` и заполни своими словами.

Правила, которые важно соблюдать с первой же заметки:
- **Максимум 10 строк.** Длинная заметка = не поняла, попробуй ещё раз.
- **Только свои слова.** Копипаста = заметки нет.
- **Поле «сначала я думала, что…» — обязательно.** Там живёт настоящее понимание.

## Если день не задался

Нормально, если что-то не встало с первого раза. Ненормально — сидеть над этим молча и до последнего.

Порядок действий при затыке:
1. Прочитай **последнюю строку** ошибки. В ней почти всегда суть.
2. Скопируй эту строку в поиск целиком. Первые три ссылки решают 80% проблем.
3. Перезапусти терминал. В Windows это чинит удивительно много.
4. Поборолась сама и не вышло — зови на помощь. Правило про борьбу существует, чтобы ты училась, а не чтобы страдала.

И запиши затык в `notes/pitfalls/`. Сегодняшняя ошибка установки — это уже опыт, который потом сэкономит тебе вечер.
