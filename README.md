# skill-boost

Рабочая среда для пути из нуля в ML-инженера.

**Первый раз здесь? → открой [ONBOARDING.md](ONBOARDING.md).** Этот файл понадобится после него.

---

## Устройство

```
skill-boost/
├── ONBOARDING.md      Первый день. Настройка с нуля.
├── README.md          Этот файл. Как жить дальше.
├── plans/             Роадмапы и планы. Читаешь, не меняешь.
├── work/              Одна папка на блок из плана.
├── projects/          Артефакты — законченные проекты из плана.
├── notes/             Заметки. Главная ценность репозитория.
│   ├── _templates/    Три шаблона
│   ├── concepts/      Почему работает
│   ├── recipes/       Как сделать
│   └── pitfalls/      Что сломалось
├── pyproject.toml     Какие библиотеки нужны проекту
└── .venv/             Окружение. В git не попадает, пересоздаётся одной командой.
```

**`work/` — грязная зона.** Черновики, эксперименты, неудачные попытки. Папка на каждый блок плана, имя — номер и тема: `00-python`, `01-gradient`. Ничего не удаляй: потом полезно посмотреть, как ты думала раньше.

**`projects/` — чистая зона.** Сюда попадает только то, что доведено до конца и имеет README с честными результатами. Из плана: *«Артефакт или блок не закрыт»*.

## Тренажёр по Python — для Фазы 0

Python-часть Фазы 0 проходится в отдельном приватном репозитории **[python-handbook](https://github.com/govnejri/python-handbook)**. Это офлайн-копия хендбука Яндекса «Основы Python»: теория, 305 задач с примерами и проверка решений прямо в VS Code (`Ctrl+Shift+B`). Тренажёр заменяет книгу Sweigart и Exercism из плана.

Он живёт **рядом** со skill-boost, а не внутри: у него своя история в git.

```
учёба/
├── skill-boost/       этот репозиторий: work/00-python, заметки, проекты
└── python-handbook/   тренажёр: теория, задачи, проверка
```

**Как получить.** Прими приглашение в репозиторий (придёт письмом от GitHub). Потом в папке, где лежит skill-boost:

```powershell
git clone https://github.com/govnejri/python-handbook.git
cd python-handbook
uv sync
```

Дальше — по README тренажёра: там установка, VS Code и порядок работы.

**Как совмещать.**

| Что | Где |
|---|---|
| Вопрос блока, черновики, numpy-эксперименты | `skill-boost/work/00-python/` |
| Теория и задачи, коммит после каждого занятия | `python-handbook/` |
| Какие задачи решать — ядро из 164 задач | `python-handbook/PLAN.md` |
| Заметки | `skill-boost/notes/` — как всегда |
| Проект Фазы 0 «CSV → статистики → графики» | `skill-boost/projects/` |

> Материалы хендбука принадлежат Яндексу. Не копируй теорию и условия в skill-boost, если он публичный: ссылка на тренажёр — да, сами тексты — нет.

## Два трека и где развилка

Планов два: **speech ML** (распознавание и синтез речи) и **классический ML** (таблицы, бизнес-задачи, MLOps).

**Фазы 0 и 1 общие в обоих.** Python, инструменты, градиентный спуск, линейная алгебра. Ничего выбирать не нужно — иди по любому из практических планов, они на этом участке совпадают.

**Развилка — после фундамента.** К этому моменту ты уже пишешь код и понимаешь, что такое обучение модели, поэтому выбор будет осознанным, а не по названию.

| | Speech ML | Классический ML |
|---|---|---|
| **С чем работаешь** | Звук, речь, аудио | Таблицы, логи, бизнес-данные |
| **Дальше по плану** | Нейросети → DSP → ASR → TTS | pandas/SQL → бустинги → нейросети |
| **Финальные проекты** | Своё распознавание речи, свой синтез голоса, голосовой ассистент | Кредитный скоринг, рекомендации, прод-сервис с мониторингом |
| **Железо** | С фазы 5 нужна GPU (аренда или своя) | Ноутбука хватает почти до конца |
| **Порог входа** | Выше: нужен сигнальный анализ и математика | Ниже: результат виден быстро |
| **Рынок** | Уже, но и конкуренция меньше | Шире, больше вакансий |

Выбрала трек — дальше идёшь только по нему. Второй никуда не денется.

## Рабочий цикл

Из практического плана. Пропорция не меняется на всех фазах:

| Что | Доля времени |
|---|---|
| Теория | 13% |
| Код | 74% |
| Заметки и ревью | 13% |

Если теория растёт — ты свернула не туда.

**Начало блока — вопрос.**
Одной строкой: что именно ты сейчас не умеешь. Не «изучить градиентный спуск», а «не понимаю, почему шаг обучения нельзя сделать большим». Записываешь в `work/NN-тема/README.md` первой строкой.

**Теория — до порога запуска.**
Читаешь ровно до момента, когда можешь начать писать код. Дальше стоп, даже если «не всё понятно». Непонятное доберётся практикой.

**Код — основная часть.**
Своя реализация → сравнение с эталоном → переписывание → сломать и починить.

**Заметки — только после кода.**
Не конспект источника. Своими словами, максимум 10 строк.

**Ревью в конце цикла.**
Заметки этого блока плюс одна случайная старая.

## Команды, которые нужны каждый день

```powershell
uv run python work/00-python/script.py    # запустить скрипт
uv run jupyter lab                        # открыть ноутбуки
uv add имя_библиотеки                     # поставить новую библиотеку
uv sync                                   # восстановить окружение (после git clone)

git add .                                 # подготовить изменения
git commit -m "что сделала"               # сохранить
git push                                  # отправить на GitHub
git log --oneline                         # посмотреть свою историю
```

**Коммить в конце каждого занятия.** Не «когда получится красиво» — сломанный код в истории полезнее, чем его отсутствие.

## Признаки, что метод сломался

Проверяй регулярно. Из практического плана:

- Заметок больше, чем кода → скатилась в конспектирование
- Заметки длинные и красивые → пишешь для воображаемого читателя
- Не возвращаешься к старым → система мертва
- Копируешь код из туториала и «понимаешь» → не понимаешь

И пять способов провалить план целиком:

1. Смотреть, а не писать
2. Прыгать вперёд, потому что скучно
3. Гнаться за SOTA-числами
4. Копить теорию «на потом»
5. Работать без логов и git

## Про темп

Единственный измеритель прогресса — **закрытые блоки**, а не пройденное время. Блок закрыт, когда есть артефакт в git и ты можешь ответить на контрольные вопросы вслух, не глядя в код.

Идти медленнее, чем казалось вначале, — норма и ни о чём не говорит. А вот если блоки перестали закрываться и ты буксуешь на месте — это сигнал, что где-то пропущен фундамент и надо вернуться назад, а не давить дальше.

Контрольные точки — в конце каждого роадмапа.

## Техническая заметка на будущее

Сейчас всё работает нативно на Windows — для фаз 0–3 этого достаточно с запасом.

Начиная с фазы 4 (GPU, обучение нейросетей, а для speech-трека ещё и аудио-библиотеки) удобнее переехать на **WSL2** — это Linux внутри Windows, ставится одной командой, файлы остаются на месте. Возвращайся к этому вопросу тогда, раньше не нужно.
