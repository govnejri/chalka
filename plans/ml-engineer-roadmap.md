# Роадмап: от нуля до уверенного мидл ML инженера

**Старт:** Python на нуле или почти на нуле.
**Финиш:** можешь взять бизнес-задачу, довести от сырых данных до работающего в проде решения и обосновать каждое решение.

---

## Как пользоваться этим документом

**Принцип:** сначала задача, которую текущими средствами решить больно, потом инструмент. Не учи инструмент до того, как почувствовал проблему.

**Распределение времени:**
- 60% — писать код
- 20% — теория
- 20% — читать чужой код и разбирать свои ошибки

**Правило проверки:** в конце каждого блока — вопросы. Не можешь ответить вслух своими словами, не глядя в код — блок не закрыт.

**Главное отличие ML-инженера от «человека, который обучает модели»:** умение правильно поставить задачу, выбрать метрику и не обмануть себя на валидации. Архитектуры вторичны. Это отражено в порядке фаз.

# ФАЗА 3. Классический ML

**Зачем:** большинство реальных задач в индустрии решаются здесь, а не нейросетями. И именно тут закладывается главный навык — не обманывать себя.

### Блок 3.1 — Метрики и валидация

> **Самый важный блок всего роадмапа.** Это то, что отличает мидла от джуна сильнее, чем любые архитектуры.

- Train/val/test, кросс-валидация, стратификация
- **Утечки данных (leakage)** — все формы: по времени, по группам, через таргет-энкодинг, через препроцессинг до сплита. Главный убийца проектов
- Разбиение по времени для временных данных
- Классификация: ловушка accuracy, precision/recall, F1, ROC-AUC vs PR-AUC — когда какая
- Калибровка вероятностей, Brier score
- Регрессия: MAE, RMSE, MAPE, R² — и когда какая врёт
- Ранжирование: NDCG, MAP, MRR
- **Бизнес-метрика vs прокси-метрика** — почему модель с лучшим AUC может ухудшить продукт
- Baseline: всегда начинать с тупейшего решения

**Код:** самому воспроизвести утечку данных, получить нереально хороший результат на валидации, найти причину. Это упражнение стоит любого объёма теории.

### Блок 3.2 — Линейные модели и основы
- Линейная и логистическая регрессия «по-взрослому»
- L1/L2 регуляризация, что делает каждая
- Bias-variance tradeoff
- Масштабирование признаков и когда оно обязательно
- kNN, наивный Байес, SVM — концептуально
- scikit-learn API: `fit/predict/transform`, `Pipeline`, `ColumnTransformer`

### Блок 3.3 — Деревья и градиентный бустинг

> Самая практически ценная модель в индустрии. На табличных данных бустинг до сих пор бьёт нейросети.

- Решающее дерево: критерии разбиения, gini, энтропия, переобучение
- Бэггинг, случайный лес
- **Градиентный бустинг: реализовать простую версию самому** — на деревьях-пеньках, чтобы понять идею последовательного исправления ошибок
- XGBoost / LightGBM / CatBoost: гистограммы, leaf-wise vs level-wise, обработка категорий, ordered target statistics
- Подбор гиперпараметров: Optuna
- Интерпретация: feature importance и почему она врёт, **SHAP**

### Блок 3.4 — Работа с признаками
- Категориальные: one-hot, target encoding (и утечка внутри него), частотное кодирование
- Числовые: шкалирование, биннинг, лог-преобразование
- Признаки из дат, циклическое кодирование
- Агрегаты по группам, оконные признаки
- Текст: TF-IDF
- Отбор признаков
- Несбалансированные классы: веса, порог, undersampling, почему SMOTE редко помогает

### Блок 3.5 — Обучение без учителя
- Кластеризация: k-means, DBSCAN, иерархическая
- Снижение размерности: **PCA** (и его связь с SVD), t-SNE, UMAP
- Поиск аномалий: Isolation Forest

### Блок 3.6 — Статистика и эксперименты
- Распределения, ЦПТ, доверительные интервалы, бутстрап
- Проверка гипотез, p-value и его типичные искажения
- Множественные сравнения
- **A/B тесты:** размер выборки, мощность, MDE, подглядывание, типичные ошибки
- Основы причинности: корреляция ≠ причинность, конфаундеры

**Это точка №1.** Ты уже можешь брать реальные табличные задачи и делать их профессионально.

**Проект:** соревнование на Kaggle с табличными данными — довести до топ-30%, написать разбор своего решения.

### Проверка
- Назвать пять способов допустить утечку данных
- Когда PR-AUC информативнее ROC-AUC?
- Почему feature importance из бустинга может обмануть?

> Самая тяжёлая точка. Прошёл — дальше легче.

### Блок 4.2 — Автоград

Ты только что полдня выводил градиенты для **двух** слоёв. Слоёв бывает пятьдесят. Вот теперь автоград — не магия, а решение твоей проблемы.

- Вычислительный граф, обратный обход
- **Написать micrograd**, расширить до тензоров

- GPU, чекпоинты

**Код:** та же сеть в PyTorch, сравнить с numpy-версией построчно.

# ФАЗА 7. LLM

**Зачем:** сегодня это не отдельная ниша, а базовое требование почти в любой ML-вакансии.

### Блок 7.1 — Устройство
- Современный стек: RMSNorm, SwiGLU, GQA/MQA, RoPE и масштабирование контекста
- **FlashAttention** — почему важна IO-aware реализация, memory-bound vs compute-bound
- Scaling laws, Chinchilla-оптимальность
- Параллелизм: data / tensor / pipeline, ZeRO, FSDP
- Стадии: предобучение → SFT → выравнивание (RLHF, DPO)
- Сэмплирование: температура, top-p, top-k, влияние на поведение

**Код:** обучить небольшую LM с нуля на своём корпусе.

### Блок 7.2 — Прикладной слой
- Промптинг как инженерная дисциплина, не как эзотерика
- **RAG:** чанкинг, эмбеддинги, векторные БД, гибридный поиск, реранкеры
- **Оценка RAG** — где проваливается большинство проектов: релевантность контекста, faithfulness, полнота
- Function calling, агенты, инструменты, циклы планирования
- Структурированный вывод, валидация схем

### Блок 7.3 — Адаптация и инференс
- Когда файнтюн, когда RAG, когда просто промпт — самое частое архитектурное решение
- **LoRA / QLoRA**, PEFT
- SFT на своих данных, подготовка датасета
- DPO концептуально
- Инференс: KV-cache, paged attention, квантизация (GPTQ, AWQ, fp8), спекулятивный декодинг, continuous batching
- Развёртывание: vLLM, TGI
- Экономика: токены, стоимость, кэширование
- **Оценка LLM-систем:** свои эвалы, LLM-as-judge и его ограничения
- Безопасность: инъекции промптов, утечки данных, гардрейлы

**Это точка №3.** Можешь собрать и оценить LLM-продукт целиком.

# Пять способов провалить этот план

1. **Пропустить SQL и валидацию, прыгнув к нейросетям.** Это ровно то, что делает большинство, и ровно поэтому большинство застревает на джуне.
2. **Смотреть, а не писать.** После каждого видео — минимум 15 строк своего кода.
3. **Гнаться за метриками в отрыве от смысла.** Модель с лучшим AUC регулярно оказывается хуже для продукта.
4. **Копить теорию «на потом».** Математика подключается по мере надобности.
5. **Не доводить проекты.** Пять недоделанных ноутбуков стоят меньше одного развёрнутого сервиса.
